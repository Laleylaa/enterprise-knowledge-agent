# AI 使用说明

本项目使用 Codex 辅助开发，参与范围、个人贡献及验证情况如下。

## AI 使用范围

| 阶段 | AI 辅助内容 | 验证方式 |
| --- | --- | --- |
| 需求与方案 | 梳理验收点，提供方案选项与取舍，根据多轮讨论起草和修订需求文档、技术方案 | 对照题目要求、讨论结论及验收场景检查 |
| 代码实现 | 实现模型与框架接入、检索与原文读取、引用校验、会话、执行预算及 CLI | 自动化测试、离线 Mock 与真实模型运行 |
| 测试与文档 | 编写测试和合成资料，整理实际输出、Trace 及交付文档 | 核对运行结果与材料链接，AI 辅助阅读回答及引用原文 |

## 个人贡献与具体修改

我通过与 Codex 多轮讨论、质疑方案假设和确认取舍，逐步明确项目需求与技术方案，并在开发中继续审阅结果、提出修改要求：

- **需求澄清与范围界定**：明确题目要求、项目约定与设计假设的边界；纠正初稿将合成制度资料列为每次问答输入的理解，明确资料由项目预置；讨论资料外问题、冲突处理和对话历史的边界，控制项目范围。
- **方案评审与技术取舍**：要求先明确知识获取方式和模型、程序的分工，再选择框架；质疑检索算法、返回粒度和渐进式读取混为一谈的方案，推动明确分块与读取契约；指出程序不能用固定规则替代适用范围和冲突的语义判断，并要求正常流程、异常处理及验证路径与需求文档对应。
- **开发中的设计改进**：提出取证与回答分离，由程序直接传递原文，并分别约束两个阶段的职责；针对追问丢失引用，追查前轮原文是否已取得，指出跨轮证据复用缺口并提出修复要求。
- **验证与范围控制**：质疑固定措辞断言造成的误报，要求按业务含义核对回答和引用；区分题目必验、核心扩展与开发诊断，要求最终材料由当前代码完整重跑生成，并同步可复现的导出入口。

讨论确认后的文档修订、代码实现、测试执行及材料整理由 Codex 落实。

在冲突处理的修订中，Codex 审阅此前通过的 Trace 时发现，文档冲突尚未解决，取证却被标为 `sufficient`（证据充分），原测试漏查取证原因。我据此明确：取证阶段报告证据状态，回复阶段判断最终任务状态，不能将查到信息直接视为证据充分。Codex 增加 `conflict`（冲突未解）状态，调整提示词与状态处理，补充取证原因断言，并保留冲突后查证动作和最终状态检查。冲突与适用关系的验证纳入正式验收批次，实际行为见[两阶段状态与动态决策验证](03-evaluation.md#3-两阶段状态与动态决策验证)。

## 验证结果与使用边界

仓库保存的[测试汇总](../examples/submission-check/summary.json)记录 54 项测试全部通过；实际输入、输出与 Trace 见[运行记录](../examples/submission-check/cases.md)，验证范围与限制见[评估文档](03-evaluation.md)。

- 离线 Mock 只验证流程，不证明真实模型决策效果；真实模型结果仅支持已覆盖场景。
- 测试由 Codex 执行并辅助核对回答与引用。我在开发中审阅具体输入、输出和失败过程，提出判断与修改要求。自动测试和回答核对的结论限于已覆盖场景，已知限制见评估文档。
