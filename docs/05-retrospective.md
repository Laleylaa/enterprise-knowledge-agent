# 项目复盘（工程事实草稿，待本人核实）

## 最难的问题

关键难点是区分“检索到了相关内容”和“足以回答当前问题”。片段可能包含期限但缺适用范围；检索降级也不代表已有原文失效。最终做法是让模型每次观察后审查问题、范围、必要条件和冲突，程序只守住真实引用和执行边界。

另一个难点是自动测试通过并不保证回复合格。实际记录出现过把通知改成口头通知、将暂时无法核实说成无效、只问当前范围却附加其他期限。应保留原始输出并阅读核对，而不是不断叠加关键词断言或只展示成功截图。

## 从验证中得到的改进

提示词按职责组织，工具规则放到工具介绍；充分证据可以直接结束，取消搜索已充分仍必须重读的要求。输出约束保留原文起算条件和用户明确提供的事实，不将资料缺失推导为事实不存在。测试按必验业务、重要补充、基础契约分开，开发期的重复矩阵本地保留，降低评审成本。

## 下一步

按当前评估中的缺陷做有针对性的改进，增加独立人工核对与不同表述样本，而非反复抽样直到全绿。扩展资料规模后再评估召回与成本。个人实际工时、亲自遇到的问题及学习收获由本人补充；本文不冒充本人独立完成的经历。
