# 企业知识问答 Agent — 产品需求文档

## 1. 背景与目标

员工查询企业制度时，需要在制度文件和 FAQ 中寻找条款、确认适用条件，并核对不同文件的规定是否一致。本项目面向这类查询，设计一个能够查阅资料、解释规则并提供原文依据的问答助手。

产品目标是让员工在一次问答或必要的澄清后，了解：

- 当前问题适用什么规定，具体条件是什么。
- 答案来自哪份文档，原文如何表述。
- 哪些事项仍缺少依据，接下来需要补充什么信息。

预期价值是减少员工查找、阅读和对照制度的工作量。回答质量以结论准确、引用有效、适用条件完整及缺口清晰为判断依据。

## 2. 产品范围

| 维度 | 范围定义 |
| --- | --- |
| 业务内容 | 差旅报销、凭证与补交、请假、设备借用和账号权限等员工制度问题 |
| 使用方式 | 本地 CLI，支持单次提问和连续对话，可导入已有历史 |
| 知识来源 | 预置的合成制度与 FAQ，作为问答的业务依据 |
| 对话能力 | 上下文追问、澄清衔接、用户条件更正和话题切换 |
| 离线体验 | 用户主动选择 Mock 模式，体验固定场景的问答流程；输出标明离线模式 |
| 范围外事项 | 产品知识问答、真实业务办理、用户上传或管理资料、自动恢复历史会话、网页界面、线上部署及生产级权限管理 |

问答聚焦预置资料能够支持的制度解释。未提供的制度细节作为资料缺口处理，具体员工的审批、付款或权限状态需由相应业务系统确认。Mock 用于离线流程体验，真实模型的决策与回答质量通过真实调用评估。

## 3. 用户流程与输入输出

### 3.1 用户流程

1. 员工启动 CLI，从新对话开始，或导入已有历史继续提问。
2. 员工提出问题，助手结合相关历史理解所问事项，查找对应制度。
3. 助手给出回答、原文引用、资料缺口和任务状态；缺少必要条件时，提出具体澄清问题。
4. 员工补充信息后继续处理，也可追问其他细节、切换话题或退出。

会话历史在本次运行内保留，方便员工连续交流。退出后结束会话，重新启动时由用户决定是否导入历史。运行记录另行保存，供后续核查回答和查证过程。

### 3.2 输入与资料

问答输入包括当前问题和可选对话历史。独立问题直接处理；连续对话沿用本次运行的相关历史，用户无需重复说明已经明确的条件。

知识资料预先配置，每份文档以文档 ID 标识，并附版本日期和正文。文档 ID 在同一资料集内唯一，版本日期用于辨认资料版本。正文保留制度的适用对象、条件、期限及例外说明，供检索、阅读和引用。

资料围绕员工常见问题组织。同一事项可以关联多份文档，例如报销期限与凭证要求分别说明；不同范围的规定、资料缺口和相互矛盾的条款也应保留，供问答过程识别和查证。

### 3.3 回答内容

| 内容 | 展示要求 |
| --- | --- |
| 回答 | 直接说明当前问题的结论及必要条件；无法确定时解释原因 |
| 引用 | 将结论关联到文档 ID、版本日期与原文片段，方便员工核对；无有效引用时显示“无” |
| 资料缺口 | 列出尚未明确的规则、适用信息或未完成的必要查证；无缺口时显示“无” |
| 任务状态 | 标明已解决、待补充信息、未解决或未完成 |
| 必要追问 | 说明需要用户补充的具体条件或文件线索 |

回答使用自然语言和清晰的引用标记。内部证据标识、工具调用细节和运行诊断放在运行记录中，业务答复只呈现员工理解和核查问题所需的内容。

## 4. 问答流程与业务规则

### 4.1 查找资料与决定下一步

问答围绕“当前问题还缺少什么依据”展开。取证模型结合问题与历史确定查证对象，选择查找相关制度或读取指定原文，判断原文是否充分、是否缺资料或存在未解冲突。回复模型依据交付的原文组织答案、引用、缺口和必要追问，并判断最终任务状态；对象不明确时，由回复模型向用户澄清。

- **文档检索：** 根据问题寻找相关条款，适用于尚不清楚依据位于哪份文档的情况。
- **片段读取：** 根据检索线索或用户指定的文档，查看原文及相关上下文，补足适用范围、起算条件或冲突关系。

每次工具返回后，取证模型结合原文和执行结果决定下一步。例如，查到报销期限但尚不清楚适用范围时，继续读取相关条款；检索未找到所需规定时，调整查询方向；原文已支持所问结论、必要条件明确且没有影响结论的未解冲突时，结束取证并交由回复模型作答。经过针对性查证仍缺依据时，如实交付证据缺口。

### 4.2 形成答案与处理冲突

回答以经核验且适用于当前问题的原文为依据，包括本轮取得的原文和会话中可复用的原文；保留其中的数值、起算点、适用条件和限制，引用片段与原文保持一致。问题涉及多个事项时，分别说明有依据的结论和仍待查证的部分。

不同文件对同一事项给出矛盾规定时，先核对适用范围、替代关系和优先级。只有文档提供明确依据，且能够匹配用户情况时，才据此选择适用规则；日期较新、期限更短或文档名称不同，本身不能作为选择依据。

取得冲突双方的原文不等于证据充分。合理查证后仍无法确定适用关系时，取证阶段记录冲突未解（`conflict`），保留双方原文和待确认事项；回复阶段决定如何呈现冲突、是否需要追问以及最终任务状态。

例如，两份制度分别规定报销期限为 30 天和 15 天，却没有说明适用范围或替代关系，回答应保留两项规定及引用，并请用户确认适用制度或提供文件线索。用户已明确没有更多线索时，说明现有依据仍无法确定适用制度，将任务标记为未解决，不重复追问；取证阶段仍保持冲突未解的判断。

用户提供的个人条件可用于匹配规则，文件线索用于进一步查阅。转述通知或粘贴库外制度时，应将其作为待核实信息，不能直接用来消除原有冲突。只取得一份明确规定且未发现冲突时，可依据该文档回答；发现冲突线索后继续查证。

### 4.3 连续对话与信息不足

历史用于理解指代和用户条件；同一会话内保留已取得的制度原文，资料未变化且适用于本问时可复用，资料变化或依据不足时重新查证。用户更正情况时，以新条件匹配规则；切换话题时，转向当前问题，只保留与新问题相关的上下文。

| 情况 | 处理方式 |
| --- | --- |
| 问题含糊，历史也不能确定所指事项 | 询问问题对象，例如无历史时问“这个能报销吗”，先了解费用类型 |
| 对象明确，但缺少决定适用规则的用户条件 | 询问最小必要条件，例如国内还是海外差旅；制度内容由助手查阅 |
| 属于员工制度领域，但查证后仍缺资料 | 说明未找到哪项规定、需要补充什么资料；未找到不等于制度不存在 |
| 明显超出业务范围 | 简要说明支持的制度问答范围，结束本轮 |

### 4.4 故障与执行限制

工具失败但模型仍可用、执行额度和时间充足时，模型根据已有证据和失败原因选择重试、调整查询、换用工具或结束。例如，原文读取失败时，可尝试检索该文档的相关条款；已有资料足以回答时，可以完成答复。必要查证持续失败时，由回答模块说明受影响的事项，保留有依据的部分答案与引用，将任务标记为未完成。

每轮问答设置模型调用、工具调用额度和处理时限。额度耗尽、整轮超时、模型服务无法继续调用或用户取消时，结束本轮处理，由程序直接返回未完成状态和对应的中断原因。已取得资料和查证过程保留在运行记录中，供后续核查；此时停止生成业务答案，不再调用回答模块整理部分结论或具体缺口。

离线 Mock 由用户另行选择，原问答不因故障或中断自动切换模式。

### 4.5 任务状态

| 状态 | 使用条件 |
| --- | --- |
| 已解决 | 当前问题全部诉求有充分依据，无未解决的相关冲突或缺口 |
| 待补充信息 | 有具体澄清问题，需要用户补充条件、确认适用信息或提供可查证线索 |
| 未解决 | 正常查证后仍缺依据、冲突未解或问题超出范围，且无进一步具体追问 |
| 未完成 | 必要处理因工具或模型故障、执行上限而中断 |

状态反映整道问题的处理结果：部分回答仍应列出缺口；需要制度维护方更新资料时为未解决；需要用户回答具体澄清问题时为待补充信息。故障恢复后证据充分可以已解决，必要处理被阻断时则为未完成；工具失败后的答复与硬中断提示按第 4.4 节分别处理。

取证阶段的证据状态与上述任务状态分别记录。相同的未解冲突，在需要用户补充线索时对应“待补充信息”，在用户已无线索可补充时对应“未解决”。

## 5. 验收标准

### 5.1 核心场景

各场景使用独立、明确的资料配置，按输入、查证过程和最终答复核对业务行为。

| 场景 | 给定条件与输入 | 预期结果 |
| --- | --- | --- |
| 明确答案 | 唯一有效规定 D01 写明“国内差旅报销须在行程结束后 30 天内提交”；询问期限 | 回答 30 天及起算条件，引用 D01 原文，状态为已解决 |
| 文档冲突 | D01 为 30 天、D02 为 15 天，未给适用范围或优先级；询问期限 | 查到双方规定并进一步核实，取证记录冲突未解；回复列出双方引用，请求确认适用制度，任务状态为待补充信息 |
| 资料外问题 | 资料没有育儿假天数；询问天数 | 说明现有资料未提供天数及所需依据，状态为未解决 |
| 改写后的相似问题 | 分别问“国内差旅报销期限多久”和“国内出差回来最迟多久交报销” | 两种问法的结论、适用条件及起算点一致，均有有效引用 |
| 上下文追问 | 已讨论国内差旅，继续问“期限呢” | 正确理解指代，依据有效原文回答国内差旅期限；会话原文经核验后可复用，依据不足时补充查证 |
| 工具失败 | 取得必要依据的工具持续失败，模型仍可用且执行额度和时间充足 | 由回答模块说明查证失败及其影响，不编造答案或引用，状态为未完成 |

### 5.2 补充场景与质量标准

- **资料替换：** 将唯一有效期限从 30 天改为 20 天后，答案与引用随新资料变化；携带旧历史时也应重新查证。
- **适用关系：** 对国内和海外差旅的不同规定，按用户条件选择；用户提供额外文件线索后查阅核实，库外声明保留为待核实信息。
- **适用性与停止：** 用户仅问某规则是否适用，原文已明确支持适用或不适用时，结束取证；不继续查用户未问的替代规则，回答有据结论且任务状态为已解决。
- **冲突追问：** 用户已明确没有更多可核实线索时，保留冲突及双方引用，任务状态为未解决，不重复追问；取证状态仍为冲突未解。
- **条件更正：** 用户更正情况后，按新条件匹配规则并回答。
- **部分回答：** 回答流程能够正常完成、资料仅支持部分诉求时，交付有据结论与对应引用，列出未回答事项，状态不标为已解决。
- **硬中断：** 执行额度耗尽或模型调用无法继续时，停止后续调用，由程序返回未完成状态及对应原因；已取得的资料与查证过程保留在运行记录中。
- **运行模式：** 离线 Mock 由用户主动启用，输出标明模式，真实问答故障不自动切换模式。

引用核对同时检查原文一致性与结论支持性，重点检查数值、起算点和适用条件。冲突场景需核对双方资料的取得与后续查证过程。无依据结论、错误引用及无依据消解冲突均判为不通过。

### 5.3 验收记录

核心场景分别保留输入、实际输出和运行记录，覆盖正常回答、资料不足及工具故障。记录关联模型选择的动作、工具参数、返回摘要、后续动作及简短行动依据，便于从答案追溯到查证过程。

运行记录应分别呈现取证结束原因和最终任务状态，以核对证据判断与回复处理是否符合各自职责。

重点对比“检索充分后作答”“发现冲突后继续读取查证”“读取失败后调整取证方式”等路径，检查后续动作是否响应工具结果。真实问答和离线 Mock 的记录分开整理，实际结果与问题记录汇总至[评估文档](03-evaluation.md)。
