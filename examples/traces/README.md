# 业务流程验证 Trace

用于核对 PRD 要求的正常流、资料／信息不足、冲突、工具失败等场景中，模型是否依据实际工具观察作出合理行动，答案、引用和任务状态是否正确。

**当前未生成业务验收材料。** 已有离线和真实模型冒烟位于 `../tests/smoke/`，不能据此宣称至少三类场景或全部验收点已通过。

后续按 `<case_id>/<variant_id>/<mode>/<run_id>/` 保存：

- `input.json`：实际问题、实际历史和公开配置。
- `corpus.json`／manifest：当次合成资料快照及版本。
- `output.json`：实际答案、引用、缺口和状态。
- `trace.jsonl`：模型动作、工具调用与观察、校验和终止事件。
- `model-inputs.jsonl`、工具结果文件：复核模型实际看到的证据。
- `run-summary.json`：计数、耗时及材料状态。

无请求或无工具执行时，不生成虚假的请求／工具记录。每组用例还须有评估侧核对结果，说明预期、实际结果、过程合理性、引用支持性及判定来源，由 `docs/03-evaluation.md` 引用；期望答案不传给运行中的模型。

自动化测试也可以驱动业务验证；此时业务过程材料仍归本目录，自动断言报告归 `examples/tests/business/`，用运行 ID 关联，不复制或混淆用途。只有实际完成要求的运行与核对后才标为通过。
